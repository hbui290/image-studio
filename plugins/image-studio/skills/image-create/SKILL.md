# Image creation

Generate a new image with controlled composition, identity, and delivery size in one pass.

Routing: For multi-round generation/repairs use [image-loop](../image-loop/SKILL.md); for local fixes use [image-repair](../image-repair/SKILL.md); for mixing inspirations use [image-inspiration](../image-inspiration/SKILL.md).

## Operational checklist

0. **Memory and chat:** Run `python3 <skills>/image-verify/scripts/studio_state.py taste list --brand <brand>` and `lesson list` once. If this chat already handled another task, suggest the user start a new chat for this one: every step resends the whole history, and the store, lessons, and taste carry the memory. Read this file and each reference once per chat, and open each new result once.
1. **Requirements:** Use the host image generation tool under its own instructions (Codex: `image_gen.imagegen`; Claude Code has none built in, so use a configured image tool or hand back the prompt); never substitute another provider without stating so.
2. **Assets first:** Before generating, list what the user already has in the folders they point to and in `brand show`: logo files, fonts (`*.ttf`, `*.otf`), SVG icons, approved art, and any script that already renders their text. Use those files. To change the typeface, show two or three of the local fonts as text layers for the user to pick; never generate lettering. When the user rejects something the brand kit prescribes (a font, a color), ask once whether to change the kit, then update it with `brand set`.
3. **Brief:** Define image task, canvas size, medium, subject, composition, copy space, output format, and required checks. If no source image exists, treat the brief as intent, not reconstructed fact.
   - **Exact copy:** confirm every word, number format, and platform name once before the first render (for example "5000+" or "5,000+", "X followers" or "Discord members"); never add punctuation or words of your own. On macOS, check the finished file reads right: `python3 <skills>/image-verify/scripts/mac_vision.py ocr final.png --expect "5000+" --expect "FOLLOWERS"` (exit 1 names what is missing or misspelled).
   - **Style first:** before the first full image, settle the medium and rendering (for example 2D or 2.5D painted, not a 3D render) from the user's taste notes and the brand's approved references. With neither, make two or three small drafts in different renderings, started at the same time (Codex: parallel `image_gen.imagegen` calls), let the user pick, and record the pick with `taste add --aspect style`.
   - **Layers:** text, numbers, and logos are never generated. Generate the background without them; when the subject's size or position may change (banners, social posts), generate the subject as its own cutout with `transparent_background`. Place the subject, the logo file from `brand show`, and every line of text with `compose_layers.py`, so changing a word, the logo position, or the subject's size is an edit to `layout.json` and one run (seconds), not a new generation:
     ```bash
     python3 <skills>/image-create/scripts/compose_layers.py layout.json --out final.png
     ```
     The layout format is in the script's `--help`. It needs Pillow: `uv run --with pillow python3 ...` ([uv](https://docs.astral.sh/uv/)) or `python3 -m pip install pillow`. It prints each layer's box for checking. For a headline that must stay in a region, give the text layer a `"box": [x0, y0, x1, y1]` (shares of the canvas), `"overflow"` (`wrap`, `shrink` to the largest size that fits, or `clip`), and `"align"` (`left`, `center`, `right`); text that cannot fit exits 2 naming the layer. A PNG output stores the resolved layout, with final font sizes, in a PNG text chunk (tEXt or iTXt) named `image-studio-layout`: `python3 -c "import sys; from PIL import Image; print(Image.open(sys.argv[1]).text['image-studio-layout'])" final.png`.
     For styled lettering (gradients, shadows, letter spacing, mixed weights), use an html layer: `{"html": "<div class='t'>5000+</div>", "css": ".t{font:700 64px Cinzel;color:#F5C542}", "box": [0.1, 0.1, 0.6, 0.4], "fonts": {"Cinzel": "fonts/Cinzel-Bold.ttf"}}`. `box` is required; `fonts` maps a CSS family to a font file inside the layout's folder (a path outside it exits 2). It is rendered by headless Chromium with page JavaScript off and every network or file request blocked, so only the listed fonts and `data:` URIs load; `<script` in the html exits 2. Content or ink (text-indent, negative letter-spacing, `::before` text, shadows) past the box exits 2 "html layer does not fit its box" with the size and offset unless `"overflow": "clip"`. Html layers need [Playwright](https://playwright.dev/python/) and its Chromium, once: `uv run --with playwright==1.48.0 python3 -m playwright install chromium`, then run the script with `uv run --with pillow --with jsonschema --with playwright==1.48.0 python3 ...` (or `python3 -m pip install playwright==1.48.0`); without them a layout with html layers exits 2 with that line, and layouts without html layers do not need Playwright.
4. **Reference roles:** Assign each attached reference one role (identity, product truth, layout, material, light, style). Resolve conflicts: style cannot override an approved logo or product shape.
5. **Prompt:** Specify result, subject/action, composition, medium/style, visible details, and constraints. State reference roles explicitly. When an object's shape follows from a physical mechanism (tear, fold, grip, stacked cards, straps, cloth) you cannot state in one sentence, follow [construction-reference.md](../image-verify/references/construction-reference.md) first and write its rule into the prompt. Read [prompt-blocks.md](references/prompt-blocks.md) when writing the prompt: style block, one item per image, background rule, and the check after generating.
6. **Attach:** Attach actual selected image files; file paths written in prompt text do not attach images. Attach a geometry sketch with a legend if needed for placement, and say: "Preserve the exact layout, proportions, and perspective; do not add new elements or text."
7. **Generate & compare:** Produce one candidate (or a small set). Wait for every generation you started to finish before ending a step; never end a turn with one still running. View candidates at target delivery size. Check required content, identity, geometry, crop, and file properties before choosing by taste. Reject variants altering protected references.
8. **Record:** Save exact prompt (and the tool's `revised_prompt`, if it returns one), tool and model name, reference roles, clean output files, and `layout.json`. Never present generated text as exact. When the user approves or praises a result, record what they liked with `taste add` ([taste and lessons](../image-verify/references/project-memory.md#taste-and-lessons)).
9. **Stop conditions:** Stop after planned candidates are compared; stop and ask if references conflict unresolved or no generator is available; stop on tool failure without silent retry.
10. **Handoff:** Review with one fresh reviewer per round (never one that carried an earlier task), and do not reopen the views you handed to it. For single review, hand to [image-verify](../image-verify/SKILL.md) (read [candidate-audit.md](../image-verify/references/candidate-audit.md) only when auditing a create contract). For multi-round repair loops, continue in [image-loop](../image-loop/SKILL.md) (read [review-loop.md](../image-verify/references/review-loop.md) only when planning multi-candidate rounds).
