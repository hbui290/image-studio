# Local image repair

Fix the confirmed regions of an accepted image in one batch while keeping other pixels untouched.

A change to text, a number, the logo, or a layer's size or position is not a repair: edit `layout.json` and rerun `compose_layers.py` ([image-create](../image-create/SKILL.md) step 3). Routing: For whole-image softness use [image-enhance](../image-enhance/SKILL.md); to locate defects use [image-inspect](../image-inspect/SKILL.md); for full-image generation/loops use [image-loop](../image-loop/SKILL.md); to plan edits use [image-edit-map](../image-edit-map/SKILL.md).

Run scripts; do not read their source - use `--help` for usage.

## Operational checklist

0. **Memory:** If not in context, run `python3 <skills>/image-verify/scripts/studio_state.py brief` (no store: `taste list` and `lesson list` instead) (see [using the store in a skill](../image-verify/references/project-memory.md#using-the-store-in-a-skill)). Read this file and each reference once per chat, and open each new result once.
1. **Targets:** Start from one confirmed list: at intake, run the hunt in [designer-review.md](../image-verify/references/designer-review.md) and let the user confirm the `map` once. When it found six or more high or medium problems or whole-image softness, offer a whole-image regeneration first. Fix every confirmed region in this round, each from an untouched source. Read [preflight.md](references/preflight.md) only before the first repair on a machine or in a new chat. Read [repair-rules.md](references/repair-rules.md) only when editing logos, packaging text, or transparent exports.
2. **Generate patches:** Start the patches for every confirmed region at the same time (Codex: parallel `image_gen.imagegen` calls in one step) and wait for all of them; composite them one at a time in step 3. Do not split one image between several editing agents. Generate each patch with the host image generator (Codex: `image_gen.imagegen` with `prompt`, `referenced_image_paths` = context crop + approved refs (at most 5, absolute paths), `transparent_background` for cutouts; it takes no size, so resize with [ImageMagick](https://imagemagick.org) `magick` before compositing, keeping aspect (crop or pad first; never stretch) and checking with `python3 <skills>/image-verify/scripts/studio_state.py align-check --base previous.png --patch patch.png --at X,Y --mask mask.png --out-dir align` (open its `checker.png` and `overlay.png`; exit 2: aspect differs by more than 1%); when nothing jumps or ghosts, run the same command with `--accept`, which marks `align/align.json` accepted for these exact files and position). Claude Code has no built-in generator: without one, stop and return the prompt). Do not search the disk for replacement artwork. Composite existing pixels only from a file the user supplied or an approved reference or logo in `brand show`. Read [repair-and-composite.md](references/repair-and-composite.md) only when configuring crops or masks.
3. **Composite:** When the patch position is unknown, `studio_state.py align-check --base previous.png --patch patch.png --mask mask.png --auto --out-dir align` finds `--at` (needs numpy and OpenCV; exit 1 "no reliable match" or "the patch must be resized"); `studio_state.py mask-from-diff --before previous.png --after edited.png --out mask.png` turns an edit into a mask ([masked composite](references/repair-and-composite.md#masked-composite)). Composite through a final acceptance mask with `python3 <skills>/image-verify/scripts/studio_state.py blend --base previous.png --patch patch.png --mask mask.png --at X,Y --align align/align.json --out candidate.png` (exit 2 unless that record is accepted and its hashes and `--at` match; `--no-align-check` skips it with a "registration not checked" warning, only when the patch cannot be misplaced, such as a full-size patch from the same render; it matches the patch color to the pixels around the mask, feathers the edge, and prints ring dE2000 and `seam_step`; exit 1 "color mismatch": the output is written but the patch edge disagrees with the base), then run `python3 <skills>/image-verify/scripts/studio_state.py edit-check --before previous.png --after candidate.png --mask mask.png --edge <feather>` (the command blend prints; or `--bbox <mask box>`) and open only its one view image (exit 1: pixels changed outside the mask or box, or the mask had no effect). When a protected object (product, face, logo) sits in or next to the region, draw its silhouette mask on the previous and the new image and run `studio_state.py shape-check --before-mask obj-before.png --after-mask obj-after.png` (exit 1: IoU under 0.99, box aspect changed over 1%, or the outline moved more than max(2 px, 0.1% of the long side)). For an intended straight sword, spear, staff, or gun barrel, require an independent final-pixel landmark review and run `axis-check --guide` (red pommel-to-tip line against the traced blade spine) ([bent rigid objects](references/repair-and-composite.md#bent-rigid-objects)). For object removal, check frame edges and corners, straight border strokes, glow or color spill, shadows, and occlusion at 100%, and at 200% only when the 100% view is unclear; "no recognizable silhouette" is not enough if fragments remain.
4. **Verify:** Hand to [image-verify](../image-verify/SKILL.md); the whole-image hunt runs again only before delivery. Read [candidate-audit.md](../image-verify/references/candidate-audit.md) only when running an automated candidate audit.
5. **Repeat or stop:** At most three repairs after the first candidate; when the same checks fail twice in a row ([`stop_repeated_failure`](../image-verify/references/decisions.md)), change the method. When a new method works after two failures, record it with `lesson add ... --worked` ([taste and lessons](../image-verify/references/project-memory.md#taste-and-lessons)).
6. **Gate before claiming done:** With a project store, run `gate --deliverable` once before saying done ([using the store in a skill](../image-verify/references/project-memory.md#using-the-store-in-a-skill)).
